6. ARCHITECTURE & PATTERNS
==============================================================================

PRIMARY PATTERN: MVC (Model-View-Controller)
  Model: TetrisGame, TetrisBoard, TetrisPiece
  View: TetrisView, Layout XMLs
  Controller: MainActivity

SECONDARY PATTERN: Observer (GameListener interface)
  - Decouples game logic from UI updates
  - 5 callback events: score, level, game over, board change, lines clearing

OTHER PATTERNS USED:
  - Immutability for Validation (piece.copy() for validation)
  - State Machine (game states: playing/paused/over, UI states: selection/play)
  - Strategy Pattern (piece types, difficulty levels)
  - Adapter Pattern (implicit, game data to UI)

==============================================================================
7. GAME MECHANICS
==============================================================================

BOARD: 10 columns x 20 rows (standard Tetris)

PIECES: 7 custom types (A-G, NOT standard Tetris shapes)
  A: 2-block line        E: 5-block line
  B: 3-block L           F: 5-block inverted L
  C: 5-block square+     G: 5-block plus/cross
  D: 5-block zigzag

CONTROLS:
  - Left/Right buttons (move)
  - Rotate button (clockwise, 5-offset wall kick)
  - Drop button (hold-to-accelerate gravity)

SPEED LEVELS: 1-9 (1000ms down to 200ms game tick)

DIFFICULTY:
  - Speed: 1-9 (select before game)
  - Starting Lines: 0-9 with random gaps (select before game)

SCORING:
  1 line = 100 × level
  2 lines = 300 × level
  3 lines = 500 × level
  4 lines = 800 × level

LEVEL PROGRESSION:
  New level every 1,000 points
  Level = (score / 1,000) + 1
  No level cap

==============================================================================
8. AUDIO SYSTEM
==============================================================================

SYNTHESIS:
  Sample Rate: 22,050 Hz
  Format: PCM 16-bit mono
  Volume: SFX 12%, Music 18% of max

SOUND EFFECTS (6 types):
  playMove()       1200 Hz, 30ms blip
  playRotate()     1400 Hz, 35ms blip
  playDrop()       880-660 Hz descending, 60-80ms
  playLineClear()  C-E-G-C-E arpeggio, 500+ ms
  playGameOver()   523-440-349-262 Hz, 150-400ms
  playLevelUp()    523-659-784-1047-1319 Hz, 600ms

BACKGROUND MUSIC:
  - 33-note arcade-style loop (~8.5 seconds)
  - Runs in background thread
  - Tempo adaptive: 1.0x (empty) to 1.5x (full board)
  - Music speeds up as board fills (tension building)

NO EXTERNAL SOUND FILES - All generated programmatically

10. PERFORMANCE & OPTIMIZATION
==============================================================================

TECHNIQUES:
  - Lazy rendering (invalidate() only on state change)
  - Handler-based game loop (not frame-locked)
  - O(1) board collision checks
  - Ghost piece only recalculated on collision
  - Minimal allocations in game loop
  - Grouped canvas draw operations

POTENTIAL BOTTLENECKS:
  - Starfield animation (200+ stars, ~33fps updates)
  - Audio synthesis (real-time PCM, thread-blocking)
  - Score serialization (minor, only top 10)

BATTERY EFFICIENT:
  - Handler delays prevent CPU spinning
  - Sleep between audio tone generation
  - Music paused when app pauses
  - No wake locks held

13. KNOWN BEHAVIORS & QUIRKS
==============================================================================

1. Toast duration: Both SHORT/LONG use 1-second (not Android standard)
2. Wall kick: 5-offset system allows rotation near walls (clever!)
3. Piece spawn: y=-1 (above board) for proper game over detection
4. Music pause: Stops rather than pausing (restarts on resume)
5. Down acceleration: Progressive (not uniform) for better feel
6. No hard drop: Drop accelerates gravity, doesn't instant-place
